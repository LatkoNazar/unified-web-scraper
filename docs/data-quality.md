# Відбір записів і фотографій

Після extraction та перевірки JSON Schema запис проходить `processing/admission.py`.
Він отримує статус `accepted`, `review` або `rejected` до збереження у датасет.
Підсумкові лічильники є в `summary.admission`; пояснення — в `admission.jsonl`.
Відхилені оригінали зберігаються окремо в `rejected-records.jsonl`.

У профілі `device` предмет продажу визначається за назвою та явним типом
оголошення. Чохол **для** ноутбука не стає ноутбуком через перелік сумісних
моделей. Ноутбук **із чохлом у комплекті** залишається пристроєм. Явно інша
модель відхиляється; невідомі характеристики залишаються для перевірки.
Кириличні символи на кшталт `М5` нормалізуються лише в позначеннях моделей.
Ці правила не застосовуються до профілю `generic`.

Фотографії прив'язуються до конкретного запису: через його JSON-LD,
галерею/itemprop, lazy-атрибути чи картку з точним посиланням. Власні Open Graph
метадані використовуються з перевіркою ідентичності сторінки. Загальний банер
каталогу або фото сусіднього товару не підставляються. Локальні `@id` JSON-LD
розв'язуються за спостереженими вузлами; адреси фото не генеруються.
`no_thumbnail`, `no_photo` та інші заглушки не вважаються фотографіями.

HTTP-версія сайту іноді відрізняється від браузерної. Звичайний backend `browser`
може отримати власні метадані там, де HTTP-запит повертає помилку або лише
заглушку. Перевірка фото не потребує AI. Недоступне джерело не дає підстав
вигадувати зображення.

## Виправлення історичного завершеного запуску

`scripts/repair_run.py` повторно перевіряє збережені записи й HTML без crawler
або AI-клієнта. Типово це лише попередній перегляд. `--apply` створює архів
оригінальних артефактів і backup SQLite, публікує виправлені експорти та
завершений checkpoint під тим самим `run_id`.

```powershell
uv run python scripts/repair_run.py RUN_ID --data-dir data
uv run python scripts/repair_run.py RUN_ID --data-dir data --confirmed-only --apply
```

`--confirmed-only` виносить також неоднозначні записи в `review-records.jsonl`.
Без нього вони залишаються у вибірці. Поточні відхилені рядки приховуються через
`excluded_at`; історія й оригінальні спостереження зберігаються. Нове прийняте
спостереження може знову зробити запис поточним.

`--image-evidence MAP.json` дозволяє використати окремо зібрані HTML-знімки
точних сторінок. Картинка повторно перевіряється за самим HTML; URL із карти
не копіюється наосліп. Саме локальне виправлення не виконує HTTP-запитів;
попередній збір додаткових знімків може використовувати звичайний браузер.
Первинний AI usage залишається незмінним.
