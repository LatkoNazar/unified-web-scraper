# Схема з питання та знайдених елементів

```powershell
uv run unified-parser discover "Знайди вакансії Python developer. Збери назву, компанію, зарплату, валюту, місто й URL." --search-results 3 --pages-per-site 3
```

Без `--config` команди `discover` і `search --source` автоматично створюють схему під питання.
Можна назвати обов'язкові для тебе поля, але вручну перелічувати всі характеристики
не потрібно. Готовий файл схеми не потрібен.

```text
Питання
  → AI: попередня назва сутності + поля для пошуку
  → код: перевірка плану → JSON Schema
  → збереження схеми та її hash
  → пошукові запити → знайдені сайти → crawler
  → перші знайдені елементи: JSON-LD, описи, атрибути, контекст карток
  → AI: одноразове уточнення полів і типів за фактичним вмістом
  → фіксація остаточної схеми → extraction → валідація → датасет
```

Наприклад, для питання про вакансії схема може містити `title`, `url`, `company`,
`salary`, `currency`, `location`. Це ілюстрація; фактичний перелік зберігається
в артефактах конкретного запуску.

Перед першим extraction система накопичує до трьох сторінок із придатними
елементами. Якщо знайшлася лише одна чи дві, використовує їх після завершення обходу.
Сторінки повторно не завантажуються: extraction отримує вже збережені знімки.
Для уточнення передається до трьох блоків на сторінку, разом до 8 000 символів
на сторінку; скорочені блоки мають позначку `truncated`.

Наприклад, питання «знайди ноутбуки» може спочатку дати загальні поля. Якщо в
описах є діагональ, обсяг пам'яті та статус керування пристроєм, модель може
додати відповідні числові поля й окремий статус. Це визначається вмістом вибірки,
а не фіксованим шаблоном ноутбука. Поля з опису не підтверджують заяв продавця:
невідомий статус залишається `null`.

Після уточнення схема не змінюється протягом запуску: перший і останній записи
валідуються за одним контрактом. Явно задана ручна схема залишається авторитетною
і не проходить цей етап, доки користувач не ввімкне `--auto-schema`.

## Правила

- `title` і `url` завжди є обов'язковими непорожніми полями.
- Додаткові поля допускають `null`, якщо на сторінці немає підтвердженого значення.
- Підтримуються рядки, числа, цілі числа, boolean і масиви до 100 простих значень.
- Для рядків із календарною датою доступний `format: date`, для дати й часу —
  `date-time`; значення перевіряються локально. Числові вимірювання мають окремі одиниці.
- Кількість полів обмежена: типово 20, допустимо 2–30 разом із `title`/`url`.
  CLI: `--schema-max-fields N`. Готова схема не перевищує 32 KiB у UTF-8.
- Модель повертає опис полів. Код сам складає закриту JSON Schema; модель не може
  додати довільні `$ref`, виконуваний код чи зовнішні схеми.
- Межа ціни з питання залишається умовою пошуку. Вона не стає `maximum` у схемі
  та не гарантує автоматичного відсікання всіх дорожчих пропозицій.

Довільні вкладені об'єкти автоматичний генератор поки не створює. Для складних
структур використовуй власну JSON Schema.

Генератор також складає план відображення: `properties.<field>.title` містить
людську назву, `x-unit` — одиницю, `x-display-role` — роль значення, а
`x-display.columns` — порядок полів таблиці. Це анотації представлення; вони
не звужують допустимі фактичні значення та не виконують код.

## Готова чи згенерована схема

```powershell
# Автоматична схема
uv run unified-parser discover "Знайди товари. Збери назву, ціну та URL."

# Схема з явно обраного профілю
uv run unified-parser discover "MacBook Air 15 M4" --config configs/jobs/macbooks-web.yaml

# Згенерувати нову схему навіть для явно обраного профілю
uv run unified-parser discover "Знайди ноутбуки. Збери назву, RAM, SSD, ціну й URL." --config configs/jobs/macbooks-web.yaml --auto-schema

# Використати стандартну фіксовану схему без генерації
uv run unified-parser discover "Книги про подорожі ціна" --fixed-schema

# Автоматична схема в YAML-профілі
uv run unified-parser run configs/jobs/web-auto.yaml
```

У YAML достатньо `schema_generation: {enabled: true, max_fields: 20}` і питання
в `search`; `schema_path` можна не задавати.
Коли генерація ввімкнена, файл із `schema_path` не використовується.

## Витрати, аудит і replay

Генерація використовує extraction-модель через OpenRouter; пріоритет:
`--model` → `OPENROUTER_MODEL` → `ai.model`. Вона має окремий stage
`schema_generation` у звіті, але спільний `ai.max_calls` із пошуком та extraction.
Типово потрібні два виклики: попередній план і одноразове уточнення за елементами.
Transport retries також витрачають спільний бюджет. Повторне питання й однакові
зразки можуть використати AI cache без нового виклику. Ключ контекстного cache
враховує питання, попередній план, URL джерел і фактичні блоки; ID знімка та
сторонній HTML поза відібраними блоками до нього не входять.

У каталозі запуску:

```text
schema.json             # остаточна JSON Schema для extraction
schema-generation.json  # остаточний та попередній плани, hash, результат уточнення
schema-evidence.json    # обмежена вибірка фактичних елементів для уточнення
job.json                # конфігурація та фактична схема
summary.json            # usage, помилки та шляхи артефактів
```

Невдала генерація завершує запуск до пошуку й обходу сайтів. Підміни на загальну
схему без повідомлення немає. Нова автоматична схема потребує AI, ключа та бюджету;
для `--no-ai` обери `--fixed-schema` або власний профіль.

Якщо елементи не знайдені, уточнення не викликає AI і в аудиті має статус
`no_evidence`. Якщо уточненню забракло бюджету або модель повернула невалідний
план, система явно записує попередження і продовжує з валідною попередньою схемою.
Скасоване уточнення має статус `cancelled` і не запускає extraction буфера.
Це відрізняється від помилки початкової генерації, яка зупиняє запуск.

Replay автоматичного запуску за замовчуванням використовує збережену схему, не генерує її повторно
й не виконує web search. Можна повторно обробити сторінки з `--no-ai`.
Контекстне уточнення під час replay також не повторюється: відновлюється саме
остаточна схема разом із її планом і hash.
Відсутня чи невалідна збережена схема дає явну помилку.
Явний `--fixed-schema` дозволяє замість неї застосувати ручну схему обраного профілю.
Відновлення структури не означає повторення AI enrichment: без AI поля, які потребують
LLM-розбору опису, можуть залишитися `null`.

Схема описує форму результату. Вона не підтверджує істинність заяв продавця,
наявність товару або повноту обходу сайту.

## Реальні перевірки

### Контекстне уточнення та типізований UI

Запуск `ae71e8c894d048b2b374646d74370efc` використовував три раніше збережені
HTML-сторінки OLX через injected fetcher і справжній `qwen/qwen3.7-flash`.
Це перевірка AI на збереженому вмісті, без нового crawling чи web search.
Попередній план → контекстний план → три extraction calls: **5 API-викликів**,
**3 записи**, нуль errors/warnings, **$0.000522136** за metadata провайдера.

Модель створила українські підписи, числові RAM/SSD/цикли, категоріальний MDM
та дату гарантії з фільтром дат. Діагональ у цьому прогоні вона обрала як рядок,
тому UI пропонує категорії; для кількох стандартних розмірів екрана це зручний
спосіб вибору. MDM є серед фільтрів і
доступних колонок, але модель не включила його в короткий автоматичний план.
AI-вибір колонок можна змінювати; ручна схема фіксує обов'язкові типи, а UI
дозволяє вибрати потрібні колонки без нового AI-запиту.

### Історичні перевірки до контекстного уточнення

| --- | --- | ---: |

| Вакансії: назва, компанія, зарплата, валюта, місто, технології, URL | `title`, `url`, `company`, `salary`, `currency`, `location`, `technologies` | $0.0000632 |

[MacBook](../data/schema-generation-live/macbooks-generation.json),
[вакансії](../data/schema-generation-live/jobs-generation.json).

Повний CLI-запуск **без `--config`** — `29b626165ed345cdb1a85a19b2de630c`:

Це історичний запуск із одним запитом і початком зі знайденого URL. Для повторення
цього способу обходу в поточній версії додай `--max-queries 1 --entrypoint result_url`.
Типовий новий discovery виконує три варіанти й починає з унікальних коренів сайтів.

```powershell
uv run unified-parser discover "Знайди оголошення MacBook Air 15 M4 на OLX Україна. Збери назву, URL, ціну, валюту, RAM у ГБ та SSD у ГБ." --search-results 1 --pages-per-site 4 --max-pages 4 --max-records 2 --max-calls 12 --data-dir data/schema-generation-live
```

Схема взята з кешу попереднього виклику, скомпільована й збережена перед пошуком.
Далі відбулися свіжі query planning, web search та два extraction calls.
Три завантажені сторінки, два записи, нуль errors/warnings; чотири нові AI calls
і один cache hit. Витрати цього змішаного запуску — $0.005226918 за метаданими провайдера;
це не cold benchmark генерації.

| Отриманий запис | Ціна | RAM | SSD |
| --- | ---: | ---: | ---: |
| MacBook Air M4 13″ 16/256 | 55 555 UAH | 16 GB | 256 GB |
| MacBook Air 15 M4 16/512 | 67 000 UAH | 16 GB | 512 GB |

Перший запис має 13-дюймовий екран: пошукові сайти повертають і суміжні оголошення.
Генерація схеми не додає автоматичного фільтра релевантності; цей тест перевіряє
саме створення та використання полів із питання, а не відповідність кожного оголошення 15″.
