# Дозбір тільки нових сторінок

Завершений збір можна доповнювати, не завантажуючи й не аналізуючи AI повторно
детальні сторінки, які вже успішно оброблені в тому самому контексті.

В інтерфейсі відкрий завершений запуск і натисни **«Дозібрати»**. Створиться
новий запуск із тією самою схемою та питанням. Він показує нові записи;
посилання **«Попередня вибірка»** веде до вихідного запуску. Старі записи та
їхня історія зберігаються в БД і не займають ліміт нових результатів.

```powershell
uv run unified-parser update RUN_ID --data-dir data
uv run unified-parser run configs/jobs/macbooks-m5-complete.yaml --incremental
```

Для звичайного нового пошуку в UI є налаштування **«Лише нові сторінки»**.
Еквівалент у YAML:

```yaml
incremental:
  enabled: true
```

## Що відбувається під час дозбору

```text
Повторно відкриваємо каталог / пошук / сторінки пагінації
                       ↓
Отримуємо поточні посилання A, B, C
                       ↓
Перевіряємо індекс успішно оброблених деталей
             A і B вже готові → пропускаємо
             C нове          → відкриваємо й збираємо
                       ↓
Зберігаємо C та позначаємо його URL завершеним
```

Каталоги й пошук перечитуються: без цього неможливо побачити нові посилання.
Відомі детальні сторінки пропускаються до HTTP/browser-завантаження;
їхні впізнані картки також пропускаються до AI routing/extraction.
Пошук нових сторінок може використовувати навігаційні AI-запити, якщо це
увімкнено в профілі. Дозбір не означає повну відсутність мережевих витрат.

Індекс зберігається в `data/incremental.sqlite`. Завершені URL прив'язані до
профілю задачі, питання, ефективної JSON Schema та налаштувань extraction.
Зміна схеми, моделей чи правил не повинна приховати дані, потрібні для нового
контексту. Додавання джерел або збільшення ліміту обходу не скидає історію.
Tracking-параметри URL прибираються; параметри, що визначають ресурс,
залишаються.

## Які сторінки залишаються для обробки

- Нові URL деталей.
- Деталі, що раніше повернули помилку або не завершили extraction/збереження.
- Сторінки, для яких відома лише картка каталогу: їх можна відкрити для
  доповнення відсутніх полів.
- Сторінки з іншого питання, схеми або іншого контексту extraction.

Сам факт відвідування URL не робить його завершеним. Індекс оновлюється після
підтвердження типу сторінки та надійного збереження результатів або явного
відхилення запису. Для старих запусків історія переноситься обережно:
потрібні збережені докази власної детальної сторінки. За відсутності доказів
сторінка може бути прочитана ще раз.

`resume RUN_ID` відновлює незавершений запуск із тим самим ID і бюджетом.
`update RUN_ID` починає окремий дозбір завершеного запуску з новими лімітами
й окремим обліком витрат. Відкриття історії саме по собі нічого не запускає.
Він використовує збережені джерела й точну схему попереднього запуску:
новий web search та повторна генерація схеми не виконуються. Для розширення
набору сайтів запусти новий пошук із режимом «Лише нові сторінки» та тим самим
профілем, питанням і схемою.
Після крашу спочатку використовуй `resume`: саме він відновлює журнал
платних відповідей незавершеної спроби. Новий запуск не успадковує її
непідтверджені AI-запити.

Перед довірою до індексу перевіряються поточні записи БД: вилучений або
прихований у карантині запис більше не підтверджує завершену обробку.
Якщо вручну виправлено активний запис без зміни його ID, для повторного
читання потрібен `IncrementalLedger.invalidate(url)` або звичайний запуск
без incremental. Сам індекс не визначає, чи змінився вміст уже відомого сайту.

Режим «лише нові» не перевіряє зміну ціни вже готових оголошень. Для повного
оновлення існуючих даних вимкни його:

```powershell
uv run unified-parser run configs/jobs/macbooks-m5-complete.yaml --no-incremental
```

Звіт `summary.incremental` містить кількість пропущених деталей/записів,
нових завершених сторінок і посилання на батьківський запуск.
